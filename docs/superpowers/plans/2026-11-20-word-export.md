# Word Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "Download Word" button on the summary that saves an English, Confluence-style `.docx` of the retro (layout B), with the Markdown copy switched to the same English structure.

**Architecture:** A pure function turns retro data into an `ExportModel`, and both the Markdown and Word outputs render from that model. The `.docx` is built in the browser with the `docx` package, loaded through a dynamic import only when the user clicks the button.

**Tech Stack:** TypeScript, React 19, Vitest, `docx@9.16.0` (new dependency; `jszip` comes with it and is used only in tests to read the output).

**Spec:** `docs/superpowers/specs/2026-11-20-word-export-design.md`

## Global Constraints

- All fixed text is English, whatever the UI locale: `Date`, `Facilitator`, `Participants`, `At a glance`, `What went well`, `What could be improved`, `Ideas`, `Action items`, `Action`, `Owner`, `Due`, `From`, `Generated by Fox Retro`.
- Role labels: `team → Team`, `product_owner → PO`, `scrum_master → Scrum Master`, `viewer → Viewer`.
- Card authors never appear in either output.
- Date format: `20 Nov 2026` (`en-GB`, `day: "numeric", month: "short", year: "numeric"`). The file name uses `YYYY-MM-DD`.
- File name: `<slug(title)>-retro-<YYYY-MM-DD>.docx`. The slug is lowercase ASCII letters, digits and `-`. If it ends up empty, use `retro`.
- "From" texts are cut to 60 characters, with `…` added when cut.
- Cards are sorted by votes, highest first. The vote count is shown only when it is above 0.
- The title uses Word's `Heading1` style and each section uses `Heading2`. A paragraph containing Arabic gets `bidirectional: true`.

## Review Focus

1. **Empty retro** (no cards in a column, no actions): each empty section shows `None`, and the actions table is replaced by `No action items.`. Tested in Task 1.
2. **Host not in the participants list:** Facilitator shows `—`. Tested in Task 1.
3. **XML-special and emoji text** (`&`, `<`, `🎉`) must survive into `document.xml` correctly escaped. Tested in Task 2.
4. **Titles that can't be file names** (`Sprint 24 / Q4: "final"`, or an all-Arabic title): the slug stays safe, and an all-Arabic title falls back to `retro`. Tested in Task 1.
5. **Arabic card text** gets a bidi paragraph, and English cards do not. Tested in Task 2.

### Task 1: Export model and English Markdown

**Files:**
- Create: `src/lib/domain/export.ts`
- Modify: `src/lib/domain/markdown.ts`. Replace `toMarkdown(s, t)` with `toMarkdown(m: ExportModel): string`, and remove `SummaryData`.
- Modify: `src/components/retro/Summary.tsx`. Make Copy Markdown use `toMarkdown(buildExport(...))`.
- Test: `tests/unit/domain/export.test.ts`, and replace `tests/unit/domain/markdown.test.ts`.

**Interfaces:**
- Produces:
  ```ts
  export type ExportInput = { retro: RetroRow; participants: ParticipantRow[]; cards: CardView[]; totals: Record<string, number>; actions: ActionItemView[] };
  export type ExportModel = {
    title: string; dateLabel: string; isoDate: string;
    facilitator: string | null;
    participants: { name: string; role: string }[];
    stats: { participants: number; cards: number; votes: number; actions: number };
    sections: { heading: "What went well" | "What could be improved" | "Ideas"; items: { text: string; votes: number }[] }[];
    actions: { text: string; owner: string; due: string | null; from: string[] }[];
  };
  export function buildExport(i: ExportInput): ExportModel;
  export function exportFileName(m: ExportModel): string;
  export const hasArabic: (s: string) => boolean;
  export function toMarkdown(m: ExportModel): string; // in markdown.ts
  ```
  - `owner` resolves to the participant name when `owner_participant_id` matches a participant, and falls back to `owner_text` otherwise.
  - `facilitator` is the participant whose `user_id === retro.host_user_id`.

- [ ] **Step 1: Write the tests.** Build fixtures with 3 columns, votes, 2 actions and an Arabic card.
  - Sections come in the order went_well → to_improve → ideas, with the headings shown above, and items are sorted by votes, highest first.
  - `participants` maps roles to `Team`, `PO`, `Scrum Master` and `Viewer`. `facilitator` is the host's name, and is `null` when the host is not among the participants.
  - `stats` equals {participants, cards, the sum of totals, actions}.
  - `from` holds the linked card texts. A text of 80 characters becomes 60 characters ending in `…`.
  - `dateLabel` is `"20 Nov 2026"` for `created_at: "2026-11-20T10:00:00Z"`, and `isoDate` is `"2026-11-20"`.
  - `exportFileName`: `"Sprint 24 / Q4: \"final\""` → `"sprint-24-q4-final-retro-2026-11-20.docx"`, and `"ريترو السبرنت"` → `"retro-retro-2026-11-20.docx"`.
  - Card authors: build the model from a card whose view carries an author name, then check that `JSON.stringify(model)` does not contain that name.
  - `toMarkdown`: the output contains `## What went well`, `## Ideas`, and `- [ ] Fix CI — Omar (27 Nov 2026)`. An empty column renders `- None`, and no actions renders `No action items.`.
